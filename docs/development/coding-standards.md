# EXAMCHAIN — Coding Standards

## General

- **Language & Framework versions:** Java 25, Spring Boot 4.1.x, TypeScript 5, Go 1.21+ (chaincode)
- **No hardcoded secrets.** All configuration via environment variables or Vault.
- **No `System.out.println` for logging.** Use SLF4J (`@Slf4j` / `LoggerFactory`).
- **Write tests.** Every module requires unit tests. Security modules require negative tests.

---

## Java / Spring Boot

### Naming

| Element | Convention | Example |
|---|---|---|
| Package | lowercase, singular | `com.examchain.exam` |
| Class | PascalCase | `ExamService` |
| Interface | PascalCase | `ExamRepository` |
| Method | camelCase | `findByExamId()` |
| Constant | UPPER_SNAKE | `MAX_RETRY_COUNT` |
| Database column | snake_case | `created_at` |

### Package Structure (per module)

```
com.examchain.<module>/
├── controller/    # REST controllers
├── service/       # Business logic
├── repository/    # Data access (JPA)
├── entity/        # JPA entities
├── dto/           # Data transfer objects (records preferred)
└── config/        # Module-specific configuration
```

### Code Style

- Use Java `record` for DTOs and value objects.
- Use constructor injection (not field injection with `@Autowired`).
- Annotate services with `@Service`, repositories with `@Repository`.
- Use `@Transactional` on service methods that modify data.
- Prefer `Optional` over null returns.
- Use Bean Validation (`@Valid`, `@NotBlank`, etc.) on DTOs.

### REST API Conventions

- Base path: `/api/v1/`
- Use plural nouns for resources: `/api/v1/exams`, `/api/v1/questions`
- HTTP methods: GET (read), POST (create), PUT (full update), PATCH (partial), DELETE
- Return `ApiResponse<T>` wrapper for all responses.
- Return `ErrorResponse` for all errors.
- Use HTTP status codes correctly (200, 201, 400, 401, 403, 404, 500).

### Error Handling

- All exceptions handled by `GlobalExceptionHandler`.
- Domain exceptions extend a base `ExamchainException`.
- Never expose stack traces in API responses.
- Log stack traces server-side at ERROR level.

## TypeScript / React

### Naming

| Element | Convention | Example |
|---|---|---|
| Component | PascalCase | `ExamList.tsx` |
| Hook | camelCase, use prefix | `useExams.ts` |
| Utility | camelCase | `formatDate.ts` |
| Type/Interface | PascalCase | `ExamResponse` |
| Constant | UPPER_SNAKE | `API_BASE_URL` |

### File Organization

```
src/features/<feature>/
├── components/    # Feature-specific components
├── hooks/         # Feature-specific hooks
├── services/      # API calls
├── types/         # Feature-specific types
└── pages/         # Route pages
```

### Code Style

- Functional components only (no class components).
- Use TypeScript strict mode.
- Prefer `interface` over `type` for object shapes.
- Prefer named exports over default exports.
- Use `cn()` utility for conditional class names.

## Database

- Use Flyway for all schema changes.
- Migration naming: `V{N}__{description}.sql` (e.g., `V2__create_exam_tables.sql`)
- Never modify a migration after it has been applied.
- Use `UUID` for primary keys (generated by PostgreSQL `uuid-ossp`).
- Use `snake_case` for all column and table names.
- Add `created_at` and `updated_at` timestamps to all tables.
- Use `TEXT` for unbounded strings, `VARCHAR(N)` only when length matters.
